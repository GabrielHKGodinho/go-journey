A goroutine leak happens when a goroutine gets stuck waiting for something that will never happen — for example, waiting for someone to read from a channel that nobody else will ever read from. To prevent it, I make sure every goroutine has an escape hatch tied to a context, using select with ctx.Done(), and I use defer right at the top for critical functions like wg.Done(), guaranteeing they run no matter which path the function exits through. To detect it, I use the goleak library in automated tests, which checks whether any goroutine is still alive after a test finishes — that catches most leaks before they reach production. For code already running, I use pprof, which exposes active goroutines and where each one is stuck, useful for leaks that only show up over days in production.
